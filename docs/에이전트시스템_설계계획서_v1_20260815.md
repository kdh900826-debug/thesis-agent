## 1. 설계 원칙 (Invariants) — v1~v32에서 추출

이 12개는 **에이전트가 위반하면 출력을 폐기해야 하는 하드 제약**이다. 프롬프트 수준 권고가 아니라 검증 게이트로 구현한다.

| ID | 원칙 | 구현 위치 |
|---|---|---|
| **P1** | **확정 사실 / 추론 분리.** 모든 문장은 `fact` 또는 `inference` 중 하나로 태깅된다. 태그 없는 문장은 출력 불가 | A3 FactSplit / 스키마 필수 필드 |
| **P2** | **정량 게이트 원칙.** 시그널 등급 상향은 확정된 매출·마진·현금흐름·가이던스 수치로만 가능. 정성적 해자 논거·테마 코멘트는 상향 근거로 **부적격** | A5 SignalArbiter 전이 규칙 |
| **P3** | **잡뉴스 필터.** 매출·가이던스·마진·현금흐름·고객명·수주·양산일정 중 **하나도** 변화시키지 않는 정보는 노이즈. 버전 업데이트·시그널 변경을 트리거하지 않음 | A2 Triage |
| **P4** | **자료 등급 서열.** ①1차(SEC EDGAR·8-K·10-K/Q·회사 보도자료·IR 자료) > ②직접 인용된 경영진 발언 > ③2차 매체 > ④애그리게이터 캘린더·스크리너. **③④는 삼각검증용이며 단독 판단 근거로 사용 불가** | A1 Ingest / evidence_grade |
| **P5** | **정보 부재 ≠ 반증.** "찾지 못함"은 "없음"이 아니다. `unconfirmed`로 남기고 확인 항목에 적재 | 전 에이전트 공통 |
| **P6** | **섹터 확신 ≠ 포지션 확신.** 매크로·테마·섹터 데이터는 개별 종목 시그널 상향의 근거가 될 수 없다 | A5 |
| **P7** | **3단 분리: 계약 존재 ≠ 계약 이행 ≠ 매출 인식.** 각 단계는 별도 이벤트로 기록되며, 앞 단계 통과가 뒤 단계를 함의하지 않는다 (Horizon 1 학습) | A4 ThesisDelta |
| **P8** | **축 분해 원칙.** 새 1차 자료가 기존 비교 축의 판정을 뒤집으면, 그 축을 하위 축으로 분해해 각각 독립 재평가한다 (Exemplar Cloud 학습) | A4 / 비교 문서 갱신 |
| **P9** | **버전 감사 추적.** 정정은 파일 덮어쓰기가 아니라 **신규 버전 발행 + 정정 사유 명기**. 오류 이력은 삭제하지 않는다 | A9 Versioner |
| **P10** | **멀티플 확장 ≠ 실적 개선.** 모든 밸류에이션 변동은 분자(가격·주수)와 분모(ARR·매출·이익) 기여로 **분해 표기**해야 한다 | A7 Valuation |
| **P11** | **사전 정의 원칙.** Kill Condition·가격 라인은 사건 발생 후 만들지 않는다. 관측 가능한 정량 트리거 + 사전 정의된 포트폴리오 결과를 쌍으로 갖는다 | A6 KillWatch |
| **P12** | **무행동 기본값.** 게이트 미충족 시 기본 출력은 "행동 없음 / 등급 유지"다. 주가가 올랐다는 이유의 추격, 내렸다는 이유의 물타기는 게이트가 아니다 | A8 Portfolio |

### 1-1. 원칙 위반 자동 검출 (구현 필수)

```
VALIDATE(output):
  assert 모든 주장 문장에 claim_type ∈ {fact, inference} 존재        # P1
  assert 시그널 상향 시 evidence.quantitative == True                # P2
  assert 시그널 상향 시 evidence.scope == "company_specific"          # P6
  assert 모든 fact에 source_url + evidence_grade ∈ {1,2} 존재         # P4
  assert "정보 없음"을 부정 결론으로 사용한 문장 == 0                  # P5
  assert 밸류에이션 변동 서술에 numerator_delta/denominator_delta 존재 # P10
  else -> REJECT(output) 후 재생성
```

### 3-2. 에이전트별 계약(Contract)

| ID | 역할 | 입력 | 출력 | 실패 시 |
|---|---|---|---|---|
| **A0** Orchestrator | 사이클 스케줄, 이벤트 큐, 중복 제거 | 캘린더·워치리스트 | 작업 큐 | 큐 보류, 사람 호출 |
| **A1** Ingest | 소스 수집·등급 부여·중복 병합 | 티커, 기간, 소스 목록 | `RawItem[]` (+`evidence_grade`) | 1차 자료 미확보 시 `unconfirmed` |
| **A2** Triage | 잡뉴스 필터 / 알림 승격 판정 | `RawItem` | `promote: bool` + 사유 | 애매 → 승격(보수적) |
| **A3** FactSplit | 확정 사실·추론 분리, 추론 강도(강/중/약) 부여 | `RawItem` | `Claim[]` | 원문 불충분 시 인용 보류 |
| **A4** ThesisDelta | 기존 thesis 대비 변화 산출 | `Claim[]` + 현행 ThesisCard | `Delta[]` (강화/훼손/중립, 어느 축) | 축 매핑 실패 시 신규 축 제안 |
| **A5** SignalArbiter | 7필드 알림 생성 + 시그널 등급 전이 | `Delta[]` | `Alert` + `SignalDecision` | 게이트 미충족 → 등급 유지 |
| **A6** KillWatch | KC-1~10 + 가격 라인 상시 감시, stale 판정 | 지표 피드 | `KCStatus[]` | 데이터 stale → **"잠정 미충족"**으로 명시 |
| **A7** Valuation | 멀티플 재계산 + 분자/분모 분해 | 가격·주수·ARR·매출 | `ValuationSnapshot` | 분모 미확정 시 range 산출 |
| **A8** Portfolio | 티어/한도/시나리오 제시 (지시 아님) | 시그널·KC·밸류 | `PortfolioView` | 게이트 미충족 → "행동 없음" |
| **A9** Versioner | 문서 생성·네이밍·감사 추적 | 판정 패키지 | `.md` 산출물 | 기존 버전 덮어쓰기 **금지** |

### 6-2. 전이 규칙 (의사코드)

```python
def transition(prior, deltas, kc_status, evidence):
    # 1) Kill 우선
    if any(kc.verdict == "met" and kc.confidence == "confirmed" for kc in kc_status):
        return "🔴🔴", "kill"

    # 2) 상향 게이트 — P2 + P6 + P7
    if delta_direction(deltas) == "strengthen":
        gate = (evidence.quantitative                       # 매출/마진/현금흐름/가이던스 확정치
                and evidence.scope == "company_specific"    # 섹터·매크로 근거 배제
                and evidence.stage >= "revenue_recognized") # 계약존재/이행만으로는 불가
        if gate:
            return upgrade(prior), "holding_reinforcement"
        else:
            # 인도 완료·인증 획득·파트너십 등: 등급 유지 + 이벤트만 강화 분류
            return prior, "holding_reinforcement"

    # 3) 하향 — 상향보다 게이트가 낮다 (비대칭 설계, 의도적)
    if delta_direction(deltas) == "weaken":
        if evidence.quantitative or evidence.evidence_grade <= 2:
            return downgrade(prior), "caution_or_position_review"
        return prior, "caution"

    return prior, "neutral"
```

> **비대칭 설계 근거:** 상향은 정량 게이트 통과를 요구하고 하향은 1차·2차 자료의 정성적 훼손만으로도 가능하게 한다. 이는 v1~v32에서 "좋은 뉴스처럼 보이는 정성 재료"에 의한 과대평가를 반복적으로 차단해온 실제 운영 방식과 일치한다.

### 9-2. 서브에이전트 분해 원칙

- **A3(FactSplit)과 A5(SignalArbiter)는 반드시 분리한다.** 같은 컨텍스트에서 사실 추출과 등급 판정을 수행하면 판정 방향이 사실 선택에 역류한다(확증 편향). A3는 등급 판정 결과에 접근하지 않는다.
- **A2(Triage)는 보수적으로 동작한다.** 애매하면 승격. 잘못된 승격의 비용(알림 1건) < 잘못된 폐기의 비용(thesis 훼손 미탐지).
- **A6(KillWatch)는 다른 에이전트 출력에 의존하지 않는다.** 지표 피드에서 직접 판정한다. 서사에 의한 KC 무력화 방지.
- **A8(Portfolio)은 지시문을 생성하지 않는다.** 시나리오·한도·이격도만 출력한다.

### 11-2. 액션 아이템

**① 스코프 확정 (코드 작성 전 필수)**
- Base를 MU 단독으로 축소할지 vs 삼성·하이닉스를 참조 자산으로 유지할지 결정

**② KC 정량화 부채 해소 (P11 위반 잔존분)**
- CRCL·COIN·HOOD의 KC가 현재 정성 서술 수준이다. **USDC 유통량 하한 %, Reserve Income 감소 분기 수, AUA 순유출 규모** 등 관측 가능한 임계값을 사전 정의해야 시스템 로드가 가능하다
- NBIS·CRWV의 개별 KC도 임계값 미정 상태 (특히 CRWV 이자 커버리지 하한, NBIS 현금 하한)

**③ 3사 상대비교와 개별 판정의 분리**
- 기존 네오클라우드 Map은 "IREN 유지/교체 판단 보조" 목적이었다. 3종목이 모두 커버리지가 되면 **상대비교 결과가 개별 시그널로 자동 전이되지 않도록** 축을 분리해야 한다(P6의 종목 간 버전)
- 예: "NBIS 재무 우위"는 NBIS 상향 근거가 아니라 **IREN 대체 시나리오의 입력**일 뿐이다

**④ 상관 리스크 명시 (검증보고서 미해결 항목)**
- 초기 검증보고서가 지적한 "금리 상승 → 조달비용 → BTC 하락 → IREN 악화" 동시 발현 스트레스 테스트가 아직 정량화되지 않았다
- 신규 커버리지로 상관이 **더 집중됐다**: 네오클라우드 3사는 AI CapEx 축을 공유하고, CRCL·COIN·HOOD는 금리·크립토 축을 공유하며, MU도 AI CapEx 축에 연동된다. **7종목이 사실상 2개 축에 몰려 있다**
- 시스템에 `correlation_matrix.yaml`을 두고, 단일 KC 트리거가 동시에 영향을 주는 종목 수를 출력하도록 권고

**⑤ 사람-에이전트 경계 명문화**
- 에이전트는 후보 판정까지. **시그널 등급 확정, 버전 발행 승인, 포지션 행동은 사람**
- 특히 🔴🔴(Kill) 판정은 자동 실행 대상이 아니라 **사람 확인 요청 + 근거 패키지 제출**로 종료

**⑥ 회귀 테스트 우선 구축**
- 10장의 F1~F12를 먼저 테스트로 고정한 뒤 에이전트를 구현할 것. 이 12개는 모두 실제 발생분이므로, 통과하지 못하는 구현은 과거 오류를 반복한다

## 12. 한 줄 결론

**이 시스템의 가치는 정보 수집 자동화가 아니라 판정 규율의 자동화에 있다** — 32개 버전에서 반복적으로 위험했던 것은 정보 부족이 아니라 정성적 호재를 정량적 확인으로 오독하는 순간이었고, 따라서 구현의 핵심은 P2(정량 게이트)·P7(계약존재≠이행≠매출인식)·P10(분자/분모 분해)을 코드 수준 거부 조건으로 강제하는 것이다. 커버리지가 7종목으로 확정되면서 **상관 집중이 오히려 심화**됐으므로(AI CapEx 축 4종목 + 금리·크립토 축 3종목), 개별 종목 에이전트보다 **KC 레이어와 상관 매트릭스를 먼저 구축**해야 하며, CRCL·COIN·HOOD·NBIS·CRWV의 Kill Condition 정량 임계 미정의가 현재 시스템 로드를 막는 최우선 부채다.
